## Description
I captured network traffic from a compromised host. The attacker encrypted their communications, but I also captured the encryption key in memory. Can you decrypt and analyze the traffic?

**Files:**
- `traffic.pcap` - Network capture
- `key.pem` - Encryption key (extracted from memory)

## What's in the Capture

1. **HTTPS Traffic** - Can be decrypted with the key
2. **DNS Queries** - May contain exfiltrated data
3. **FTP Traffic** - Old school file transfer
4. **ICMP Packets** - Sometimes used for covert channels
5. **Custom Protocol** - Attacker's C2 protocol

## Tools Needed
- Wireshark - Network analysis
- tshark - Command-line Wireshark
- NetworkMiner - File extraction
- Python with scapy - Packet manipulation

## Solution Approach

### Step 1: Decrypt HTTPS
```bash
# In Wireshark: Edit → Preferences → Protocols → TLS → RSA Keys
# Add key.pem and decrypt traffic
```

### Step 2: Analyze DNS
```bash
# Extract DNS queries - look for suspicious domains
tshark -r traffic.pcap -Y "dns" -T fields -e dns.qry.name

# Data might be in subdomains
# flag-data.evil.com → "flag-data" is the exfiltrated data
```

### Step 3: Extract Files
```bash
# Use NetworkMiner or binwalk
binwalk -e traffic.pcap
```

### Step 4: Analyze ICMP
```bash
# ICMP can carry data in payload
tshark -r traffic.pcap -Y "icmp" -T fields -e data
```

### Step 5: Reconstruct Streams
```bash
# Follow TCP streams in Wireshark
# Or use tshark
tshark -r traffic.pcap -z follow,tcp,raw,0
```

## Solution Script
```python
from scapy.all import *

packets = rdpcap('traffic.pcap')

for pkt in packets:
    if pkt.haslayer(DNS):
        # Extract DNS queries
        query = pkt[DNSQR].qname.decode()
        print(f"DNS: {query}")
    
    if pkt.haslayer(ICMP):
        # Extract ICMP payload
        if pkt[ICMP].type == 8:  # Echo request
            data = pkt[ICMP].load
            print(f"ICMP: {data}")
```

## Hints
1. DNS queries often hide data in subdomain names
2. ICMP echo requests can carry arbitrary data
3. Look for unusual ports or protocols
4. File transfers often start with magic bytes (MZ, PK, etc.)
5. The key.pem decrypts the TLS traffic - use it in Wireshark
